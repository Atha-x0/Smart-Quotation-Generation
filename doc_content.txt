Project OverviewA system that eliminates manual calculation errors, speeds up quotation creation, and maintains a permanent, tamper-evident archive of every quotation and revision ever generated.The system does two jobs:Automated calculator: fetches tax codes (HSN/SAC) and computes taxable/total amounts automatically.Immutable archive: tracks every revision of every deal from first draft to final agreement, with nothing ever overwritten or deleted.Works on desktop and mobile: including full quote creation in the field with poor or no internet connectivity.2. Core WorkflowsWorkflow 1 — Manual Quotation CreationHeader auto-generated: unique Quotation Number, today's Date (editable/unlockable for backdating), Revision defaults to 0 / Initial.User enters Client Name, Address, Contact, Validity Date, Subject.Item entry: user types Item Name + Description.Auto-fetch: fuzzy search against HSN database fills HSN/SAC Code automatically.User enters Quantity and Rate; system calculates Taxable Amount and running Total Amount.Scope of Work / Technical Specifications / Terms & Conditions are added (see Section 4).Click Generate: PDF compiled and saved as [QuotationNumber]_rev[Label].pdf.Workflow 2 — Direct Excel Bulk UploadUser uploads a pre-filled Excel template with client header info and raw line items.System validates rows and shows a preview/confirmation screen before proceeding (never silent).Background job reads rows, runs HSN fetch for every item, calculates all totals.PDF generated automatically using the same rendering engine as Workflow 1.Workflow 3 — Revision & Archiving Flow (Core Feature)User opens an existing quotation and bumps the Revision Number (e.g., 0 → 1, or a custom label like 1B).User edits rates/quantities/scope/terms; totals recalculate automatically.On Generate: system creates a brand-new database row linked to the new revision — the old record is never overwritten.New PDF saved with the standardized naming pattern; old PDF remains untouched and accessible.Dashboard shows the current active revision; a History tab lists and allows download of every past revision.3. Key Improvements & Design DecisionsData IntegrityQuotation Number generated via an atomic DB sequence/counter — never “read max, add 1” in application code (prevents duplicate numbers under concurrent use).Revision stored as two fields: revision_index (integer, used for internal logic/ordering) and revision_label (free text shown to user, e.g. “1B”).One consistent file-naming pattern for all PDFs: [QuotationNumber]_rev[Label].pdf — replaces the inconsistent quotation_/renew_ naming.Every revision is a full immutable snapshot (line items, content blocks, totals) — never a diff applied to a live record.Tax & ComplianceCGST/SGST vs IGST auto-determined by comparing company state vs client state.Rounding applied at the total level per GST convention, not line-by-line.HSN fuzzy-match includes a confidence threshold; below it, the field is left blank for manual entry instead of guessing.Discount handled as an explicit field, at line-level and/or header-level.Validation & SafetyExcel bulk upload always shows a validation/preview screen (rows OK vs flagged) before PDF generation.Role-based access control for create/edit/approve/view actions.Full audit log: user, timestamp, and action recorded on every create/edit/revision.Optional PDF checksum/hash stored per file to prove archive integrity later (useful in disputes).Document CompletenessCompany letterhead, bank details, signatory/stamp block, and payment terms included in the PDF template.Validity Date drives an auto status flag: Draft / Sent / Expired / Accepted / Converted.User ExperienceDiff view between revisions showing exactly what changed (rate, qty, discount, scope, terms).Dashboard filters: client, date range, status, sales rep, category.One shared PDF-rendering engine used by both manual and Excel workflows — avoids formatting/logic drift between two renderers.4. Offline-First Architecture (Mobile Field Use)Since reps must be able to create full quotations in the field with poor/no internet, the local device is treated as the primary write target, with the server as the sync destination — not the reverse.Local Data LayerOn login (while online), sync down and cache locally: HSN/SAC master data, Scope/Spec/T&C library, recent/frequent client list.All quote creation — header, items, HSN matching, totals — runs entirely against local cached data, no network call required mid-creation.HSN fuzzy-match runs client-side (Fuse.js) against the cached dataset; optional re-validation against the live server database once back online.Local PDF GenerationOffline path generates a PDF entirely client-side so the rep can show/share it to the client immediately.Once connectivity returns, the server regenerates the canonical PDF via the main Puppeteer engine — this becomes the official archived record.Local PDFs are marked (e.g., “Draft — pending sync” watermark) until confirmed synced.Sync & Conflict ResolutionOutbox queue: every offline create/edit is written to a local queue with timestamp and device ID; flushed to server in order once online.Quotation numbering: offline quotes get a temporary local UUID; the server assigns the real sequential Quotation Number on sync, and the local record updates to match.Edit conflicts: low risk for new quotes; for the rare case of concurrent offline revisions, use last-write-wins with a full audit log entry rather than silent overwrite.Sync status visibility: every quote shows a clear status — Local Draft → Syncing → Synced/Official — and the dashboard supports filtering by sync status.Key Documentation PointsOffline data retention limit: how much local storage / how many draft quotes a device can hold before cleanup.Sync conflict policy documented explicitly (last-write-wins + audit log).“Official record” definition: the server-synced, server-generated PDF is the legal/official one; local PDFs are provisional. Important for any future dispute.7. Mobile + Desktop UI NotesItem entry table: full spreadsheet-style grid on desktop; card-based stacked layout with swipe/tap interactions on mobile — design both explicitly, don't just shrink the desktop table.Dashboard: full table + sidebar filters on desktop; card list + bottom-sheet filters on mobile.Rich-text editor (Scope/Specs/T&C): simplified, bottom-anchored toolbar on mobile.PDF preview: plan for a download/open-in-new-tab fallback since inline PDF rendering is inconsistent across mobile browsers.Build mobile-first responsive from Phase 1 onward — retrofitting responsiveness later is expensive and usually incomplete.8. SummaryThis system combines an automated tax/calculation engine with a permanent, revision-safe archive, delivered as a responsive, offline-capable PWA so sales reps can create full quotations in the field regardless of connectivity. The architecture is built around three principles:Never overwrite — every revision is a new, immutable, linked record.Never guess silently — fuzzy-matched data (HSN, content blocks) is confidence-checked and always user-editable.Never block on connectivity — local-first data and PDF generation, with server sync producing the official record.
